Testnet run

A full merchant run on public testnet, every request the shop sent recorded on its way to the server over Tor.

View .md

On 2026-10-25 ZecPy ran a full merchant story on Zcash testnet against testnet.zec.rocks, with real proofs, real blocks and real third-party transactions as memo decoys. Every request the shop sent to the light server was recorded by the leak-audit proxy, and that proxy reached the server only over Tor. Script: tools/testnet_run.py. Raw audit log: docs/testnet-run/shop-audit.jsonl.

Setup

Text
shop (ZecPy, watch-only) -> audit proxy (loopback, records) -> tunnel -> arti (Tor) -> testnet.zec.rocks
agent (ZecPy, hot)       -> ZecPy's built-in Tor                                  -> testnet.zec.rocks
signer (ZecPy)           -> no network
payer (zcash-devtool)    -> testnet.zec.rocks     (a customer's wallet, another codebase)

The shop holds a viewing key only (can_send=False); its spending key was made offline by the signer. The payer was funded with 1 TAZ from a public faucet (7cf7c141cde4844868d79c5c83a6189a435c8990fe16c1374c2d5775ac781bf7, block 4,540,684).

What the server learned from the shop

108 requests over the whole run:

Label Count Requests
public 97 GetSubtreeRoots 63, GetLatestTreeState 21, GetBlockRange 12, GetLatestBlock 1
coarse 2 GetTreeState at 4,539,999: the birthday rounded down to a 10,000-block boundary
broadcast 1 SendTransaction: the refund
identifying 8 GetTransaction: the opt-in memo fetch

No request outside the memo fetch tied anything to the shop. That covers sync, detection, confirmation, the invoices and the cold-signed refund. There was no transparent address query, no exact birthday, and no tree state at the height where a previous sync stopped. The shop never looked a transaction up by its id, apart from the memo fetch below.

The seven decoys are other people's shielded testnet transactions from nearby blocks, taken from compact blocks the shop had already downloaded. None of them belongs to this run. Publishing which one was real gives that up for this transaction, which is the point of a demonstration on testnet. On a real shop, nobody but the wallet knows.

What this run does not show

  • The agent's requests were not audited. It used ZecPy's built-in Tor directly, to show that path with a real send. The audit proxy can only record a wallet that talks to it on loopback.
  • Tor hides the network address, not the request content. The proxy sees content, then forwards it over Tor. The server saw the shop's requests arrive from Tor exits.
  • No reorg happened during the run, and no pool crossing was attempted: testnet funds arrive in Ironwood, as on mainnet since NU6.3.
